# 2026-11-25 · Claude Code session 1

**Phase:** 1 · Foundations
**Time spent:** ~1h

## Done

- Wrote [ADR-0004](../docs/decisions/0004-toml-schema-stdlib-frontmatter.md): TOML schema read with `tomllib`, and a stdlib parser for a strict frontmatter subset instead of PyYAML.
- `schema/note-types.toml`: the six note types from `docs/design.md` (folder, required fields, statuses), common fields, and a kind per field (`string`, `int`, `bool`, `date`, `list`).
- `scripts/lib/frontmatter.py`: `split`, `parse`, `dump`, `render`. Flat mapping only; strings (plain, double- or single-quoted), ints, bools, null, block and flow lists. Raises `FrontmatterError(line=N)` on anything else.
- `scripts/lib/schema.py`: `load` sanity-checks the schema (folders must sit under `wiki/`, every field declared); `validate(meta, path, schema)` returns a list of problems (missing or mistyped fields, bad dates, status, `generated: true`, wrong folder, `..` escapes).
- `tests/`: 123 tests, `python3 -m pytest` → `123 passed in 0.07s`. `pyproject.toml` holds pytest config; no runtime dependencies.
- Updated `docs/design.md`, `docs/roadmap.md`, ADR-0003, `README.md` and `docs/context.md` from `.yaml` to `.toml`.

## Learned

- YAML 1.1 (PyYAML) has more implicit types than expected. A bare `=` is a `!!value` tag and crashes `safe_load`; `yes`/`no`/`on`/`off` are booleans; `0755` is octal, `1:30` is sexagesimal (90), `3.10` is the float 3.1. The parser refuses all of these unquoted, and the emitter quotes any string that would read back as something else.
- Obsidian writes wikilinks in properties quoted (`"[[note]]"`). Unquoted `[[note]]` is a nested list in YAML, so it is refused.

## Problems and fixes

- A cross-check against PyYAML (fuzz: 20,000 random strings through `dump` and `parse`) found two gaps: bare `=` (above) and raw control characters (`\r`, `\x0b`, `\x0c`) in plain values, which YAML treats as line breaks or rejects. Both are now refused, and the emitter escapes control characters as `\uXXXX`. Rerun: 0 mismatches. A flow-list fuzz then gave 0 mismatches over 12,174 accepted inputs.

## Decisions

- [ADR-0004](../docs/decisions/0004-toml-schema-stdlib-frontmatter.md): TOML schema; stdlib strict-subset frontmatter parser.

### Later in the session: plugin scaffold

- Read the plugins reference and skills docs. Only `name` is required in `plugin.json`, and all components sit at the plugin root. `bin/` goes on the Bash PATH. `${CLAUDE_PLUGIN_ROOT}` is not in the Bash tool's environment, so skills call `akashactl` through `bin/`. `disable-model-invocation: true` makes a skill user-invoked only (this settled one of the unverified items in `docs/context.md`).
- Added `.claude-plugin/plugin.json` (name `akasha`, version `0.0.0`, matching `pyproject.toml`) and `bin/akashactl` (`exec python3 -I .../scripts/akashactl.py`). `-I` stops a planted `json.py` or `lib/` in the vault folder from shadowing imports; `akashactl.py` adds its own directory to `sys.path` because `-I` doesn't. `skills/.gitkeep` holds the empty skills folder.
- `scripts/akashactl.py`: a Python 3.11+ check with a clear message, because macOS `/usr/bin/python3` is 3.9 and `tomllib` would otherwise fail with an ImportError. Added `--version` and a read-only `validate [paths] --vault DIR`. With no paths, it checks every `generated: true` page under `wiki/` and skips the rest. It reports unparseable frontmatter and paths outside the vault, and exits 1 on problems or 2 on a bad vault or schema. `capture`/`apply`/`undo` aren't registered yet, so nothing pretends to work.
- `tests/test_plugin.py`: manifest fields and version match, the wrapper version, a shadowing-module test, validate behaviour including a never-writes check, the old-Python message, and a real `claude plugin validate`. `python3 -m pytest` → `137 passed in 0.95s`.
- `claude plugin validate --strict .` fails on exactly one warning: "CLAUDE.md at the plugin root is not loaded as project context". That's intended, because it's the repo's dev context, so the test runs without `--strict` and fails on any other warning. The directory checks also flag no LICENSE (required for submission) and no icon; both moved to Phase 6. `claude --plugin-dir . plugin details akasha` loads it: 0 skills, ~0 always-on tokens.
- CLI gotcha: `--plugin-dir` is a global option, so it's `claude --plugin-dir . plugin details akasha`, not `claude plugin details akasha --plugin-dir .` (the second gives "unknown option").

- `scripts/lib/gitops.py`: `commit_paths` stages and commits only the given paths (`--only`), as `Akasha <akasha@localhost>`, with an `Akasha-Operation:` trailer for `undo`. It returns `None` when the paths already match HEAD.
- `scripts/lib/capture.py`, `akashactl capture [--vault] [--dry-run]`:
  - Copies into `.raw/` with open mode `xb` (create-only), then re-hashes the copy after writing.
  - Refuses if an existing `.raw/<hash>` doesn't match its name, or if `.raw` is a symlink.
  - Re-records raw files that are missing from the manifest, and restores deleted ones.
  - Detects links with stdlib `plistlib` and `configparser`.
  - Fixture run: `6 new, 1 duplicate, 2 skipped; commit <hash>`.
- Tests: `tests/test_capture.py` (32 tests). `python3 -m pytest` → `169 passed in 3.25s`.

Problems and fixes:
- The fixture source page had `raw: 000…0` unquoted, and `validate` refused it: "would be read as a non-integer number". That refusal is correct, because unquoted YAML reads it as the integer 0. Any real SHA-256 made only of digits plus one `e` (e.g. `12e45…`) would read as a float. Akasha's emitter already quotes these; the fixture now quotes the hash. Keep in mind for hand-written notes.
- Restoring a deleted `.raw` file gave `git commit` "nothing to commit", because the bytes match HEAD. Fixed by checking `git diff --cached --quiet HEAD -- <paths>` first; this also works in a repo with no commits yet (tested).
- I miscounted the fixture's expected new files (7 vs 6) in the first test draft; the code was right.

Decisions (small, recorded in `docs/design.md` rather than an ADR):
- `.raw/manifest.json` is the only mutable file in `.raw/`.
- A vault is marked by `akasha.json` plus being a git repo root.
- Commits skip vault git hooks (`--no-verify`), so a user hook can't block or alter an Akasha write.

### Later in the session: `akashactl apply`, `--dry-run`, `undo`

- `scripts/lib/plan.py` validates a JSON plan completely before any write and raises `PlanError` with every problem at once. It checks:
  - **Plan keys:** no unknown keys; `operation` is a short lowercase name (`capture`/`undo` reserved); `log` is one line of at most 300 characters.
  - **Paths:** only `wiki/**/*.md`; no `..`, hidden parts, backslashes, symlinks, or reserved files (`index`/`log`/`hot`/`now`); outside every `personal` folder from `akasha.json`, even one inside `wiki/`, compared case-insensitively.
  - **Frontmatter:** must parse, and must pass the schema, including the folder.
  - **`create`:** must not match an existing file under any letter case.
  - **`update`:** `base_hash` must match, and the old page must be `generated: true`.
  - **Links:** every `[[link]]` / `![[embed]]` resolves Obsidian-style (by name, full or partial path, case-insensitive, or a page created in the same plan); code spans and fences are ignored.
- `scripts/lib/apply.py`:
  - Writes pages atomically, regenerates `wiki/index.md` (grouped by the schema's new `label`, linked by path) and prepends a `wiki/log.md` entry.
  - Makes one commit with the trailer; rolls back on failure; `--dry-run` shows the summary and log entry, `--diff` adds unified diffs.
- `scripts/lib/undo.py` restores the files of the newest un-undone Akasha commit from its parent, deletes files it created, and commits with `Akasha-Reverts: <sha>`. It refuses if any of those files changed since, in HEAD, the index or on disk.
- `.akasha/lock` (`O_EXCL`) is now shared by capture, apply and undo (`vault.write_lock`). `akashactl hash` prints `base_hash`.
- Smoke run on a copy of the fixture vault: dry run → apply (`commit 74fb043`) → undo restored index and log and deleted the page → a second undo said "nothing to undo".
- `tests/test_apply.py`: 63 tests, including the four the roadmap names. `python3 -m pytest` → `232 passed in 8.88s`.

Decisions: [ADR-0005](../docs/decisions/0005-apply-and-undo-semantics.md). Undo is a restore with a "changed since" refusal rather than a literal `git revert`, and it steps back through history. `index.md` is regenerated rather than appended to. Plans may only update `generated: true` pages.

Problems: a wrong expected line count in one test (10 vs 13; block lists take a line per item); the code was right.
